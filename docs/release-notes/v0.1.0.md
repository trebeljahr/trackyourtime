Track Your Time now runs on your own server from two published images. Before this release, a self-hosted copy meant building the web app on your server, and that build needs about 4 GB of memory.

Now your server builds nothing. It pulls the images, so the self-hosting guide sizes the stack for 1–2 GB of RAM. Both images cover linux/amd64 and linux/arm64, so an ARM server runs them with no emulation. Your accounts and time entries stay in a MongoDB container on that server.

## Install

You need three things:

- An Ubuntu 22.04 or 24.04 server.
- A domain with an `A` record that points at the server.
- Ports 80 and 443 open to the internet.

Step 0 of the [self-hosting guide](https://github.com/trebeljahr/trackyourtime/blob/v0.1.0/docs/self-hosting.md) installs Docker and opens the ports.

Replace `track.example.com` with your domain:

```bash
git clone https://github.com/trebeljahr/trackyourtime.git
cd trackyourtime
git checkout v0.1.0
cp .env.selfhost.example .env
chmod 600 .env
sed -i "s|^BETTER_AUTH_SECRET=.*|BETTER_AUTH_SECRET=$(openssl rand -base64 32)|" .env
sed -i "s|^APP_DOMAIN=.*|APP_DOMAIN=track.example.com|" .env
docker compose -f docker-compose.selfhost.yml pull
docker compose -f docker-compose.selfhost.yml up -d
scripts/selfhost-check.sh track.example.com
```

The check script prints one `PASS`, `FAIL` or `SKIP` line each for DNS, the containers, the certificate, port 80, the API routes and the WebSocket. Each `FAIL` line has a `fix:` line under it. When nothing fails, open `https://track.example.com/signup` and create your account.

`docker-compose.selfhost.yml` pulls these two images:

| Image | Platforms |
|---|---|
| `ghcr.io/trebeljahr/trackyourtime-server:v0.1.0` | `linux/amd64`, `linux/arm64` |
| `ghcr.io/trebeljahr/trackyourtime-client-selfhost:v0.1.0` | `linux/amd64`, `linux/arm64` |

Caddy, MongoDB 7.0 and Redis 7.4 come from Docker Hub. Caddy gets a Let's Encrypt certificate for your domain on the first request. You need no registry login, no API key and no account with any other service.

Each image carries a provenance attestation and an SBOM. `https://track.example.com/api/health` reports the commit the server image came from, in its `version` field.

The guide gives the expected output and the usual failures for every step. It also has a prompt you can give an AI assistant with shell access to your server.

To build the images from your clone instead, add `docker-compose.selfhost.build.yml` to the command. That build needs about 4 GB of memory, or less RAM plus swap.

### If you ran the stack from source before this release

The earlier compose file built both images on your server under the same names as the release images. The compose file now pulls only images it does not have, so a plain `pull` skips yours. Take a database dump, then force the pull once:

```bash
docker compose -f docker-compose.selfhost.yml exec -T mongo mongodump --uri "mongodb://127.0.0.1:27017/trackyourtime" --archive --gzip > pre-upgrade-$(date +%Y%m%d-%H%M%S).archive.gz
git fetch --tags
git checkout v0.1.0
docker compose -f docker-compose.selfhost.yml pull --policy always
docker compose -f docker-compose.selfhost.yml up -d
```

If you edited `Caddyfile`, `git checkout` stops and names it. Run `git stash`, repeat the checkout, then `git stash pop`.

To confirm the switch, run `docker image inspect --format '{{.RepoDigests}}' ghcr.io/trebeljahr/trackyourtime-server:v0.1.0`. A pulled image prints a `ghcr.io/trebeljahr/trackyourtime-server@sha256:…` entry. A local build prints `[]`.

## What you can do with 0.1.0

**Track time.** Start and stop a timer with one click, or add the time you forgot in a separate dialog. Favorites and recent work restart a job without retyping it. Idle detection can ask what to do with the time you were away. A maximum entry duration catches the timer you left running over a weekend.

**Bill for it.** Each entry keeps the hourly rate it was tracked at, so a later rate change does not reprice past work. The reports page groups totals by client, project, task, tag, day, week or month, and exports the open view to CSV and PDF. Invoices come from tracked entries, move through draft, sent and paid, and export to PDF.

**See the week.** Fill in a weekly timesheet from the keyboard. The calendar shows day, week, month and year views, and you can drag an entry and undo the drag.

**Bring your history, and take it with you.** Import a delimited text file, check the preview, and undo the whole import as one batch. Export a workspace as JSON, which imports into an empty workspace, or as CSV in the shape the importer reads.

**Use it from more than one device.** A start or stop shows on every other signed-in device without a reload. The web app, the browser extension and Raycast each keep a queue of offline changes, and send them in order when the connection returns. In Settings → Devices, you can sign out any session. A workspace can move between the hosted service and your own server, and the old server keeps its copy.

**Connect other tools.** The REST API at `/api/v1` takes scoped API tokens and publishes an OpenAPI document. Signed webhooks report entry and invoice events. An MCP server in `packages/mcp` lets an MCP client start timers, log time and run the summary report with your API token.

## Not in this release

- **No desktop or mobile app.** The iOS and Android projects build from source with `pnpm build:mobile`. The `v0.1.0` tag publishes no desktop, mobile or Tauri build.
- **No store listings.** You build the browser extension and the Raycast extension from source. Both let you pick your own server after install.
- **One account is one private workspace.** The app can't invite team members yet.
- **Anyone who reaches your domain can sign up.** The app has no setting to close registration. The guide shows how to [block the sign-up endpoint in `Caddyfile`](https://github.com/trebeljahr/trackyourtime/blob/v0.1.0/docs/self-hosting.md#accounts-and-what-admin-means-here) once your own account exists.
- **Email verification is off.** Without SMTP, the server writes password-reset links to its log.
- **No notifications, timesheet approvals or time-off tracking.**
- **Most screens are English only.** The German setting translates the language and theme controls and formats dates, numbers and money.
- **The server runs as one container.** Live sync stays inside that process, so a second replica would reach only some of your devices.

## Upgrading and pinning

`.env` pins `TRACKYOURTIME_VERSION=v0.1.0`, so an unattended `pull` never moves you to a newer release.

| Tag | Points at |
|---|---|
| `v0.1.0` | This release, and nothing else. The default. |
| `0.1` | The newest stable `0.1.x` release. |
| `latest` | The newest stable release. |

The release workflow moves `0.1` and `latest` last. First, it pulls `v0.1.0` with no registry login and starts the compose stack from it on amd64 and on arm64. Both starts must pass.

A later upgrade takes a dump, checks out the new tag, sets `TRACKYOURTIME_VERSION`, then runs `pull` and `up -d`. Nothing migrates at startup. The [Upgrading](https://github.com/trebeljahr/trackyourtime/blob/v0.1.0/docs/self-hosting.md#upgrading) section has the exact commands and the rollback.
