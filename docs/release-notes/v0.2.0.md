# Track Your Time 0.2.0

Signing in on a phone or desktop no longer requires typing a password into the app. Choose **Sign in with your browser**, sign in there, then approve the code shown in the app. The browser accepts a password, Google sign-in or an emailed sign-in link. Email links work for existing accounts when the server can send mail. They expire after five minutes and work once. Accounts with two-factor authentication still need their password and authenticator code in the browser.

The installed phone app now shows the full name **Track Your Time**. Its login fields identify the email and password to password managers. Its startup screen uses the stopwatch animation from the extension. Android can match passwords saved for `trackyourtime.dev` to the Play-signed app through the published website association. Password manager prompts still depend on the device and the selected manager.

Time entries and favorites now keep their own client. You can choose a client for an entry without changing its project. Client filters and reports follow that choice. The extension popup also shows recent entries and gives quicker feedback when you start or stop a timer.

The server now checks a session against current account state on each request. Revoking a session takes effect without waiting for its cookie cache. Timer start-time edits and stale long-timer alerts also work more reliably.

## For self-hosted servers

Update the server and client images together. This release raises the API level from 6 to 8 for independent entry clients and timer start-time edits. Older clients remain supported. Email links require configured account email delivery; servers without it continue to accept passwords.

```bash
docker compose -f docker-compose.selfhost.yml pull
docker compose -f docker-compose.selfhost.yml up -d
```

The [self-hosting guide](https://github.com/trebeljahr/trackyourtime/blob/v0.2.0/docs/self-hosting.md) covers the mail transport settings.
