A pipeline fix release. The app is byte-for-byte what v0.1.1 shipped — if you already run v0.1.1, there is nothing here for you to upgrade to.

Two checks in the release workflows refused correct input and stopped a leg that had already built successfully.

The self-host smoke test compared an image's platform list with one shell pattern asking for both architectures at once. The single space between `linux/amd64` and `linux/arm64` was consumed by the first half of the pattern, so a correct two-platform manifest could never match, and the test failed with `lists [linux/amd64 linux/arm64], expected linux/amd64 and linux/arm64` — the same set printed twice. Each platform is now checked on its own, and a genuinely single-architecture image is still rejected.

That failure is why no release so far has moved the `latest` and `0.1` tags onto an image. Only exact version tags exist in the registry today. This never affected a documented install: `docker-compose.selfhost.yml` pins `TRACKYOURTIME_VERSION` to a specific release rather than following a moving tag. If you pull `latest` by hand, pull `v0.1.2` instead.

The second fix is in the iOS release leg, which passed a `plutil` key path unquoted. The shell stripped the backslashes that stop the bundle id's dots being read as nested keys, so the workflow failed to read back the `ExportOptions.plist` it had just written correctly.

Upgrading from v0.1.1 is the usual two commands:

```bash
docker compose -f docker-compose.selfhost.yml pull
docker compose -f docker-compose.selfhost.yml up -d
```

The [self-hosting guide](https://github.com/trebeljahr/trackyourtime/blob/v0.1.2/docs/self-hosting.md) is unchanged.
